# 알뜰철도 X (RailHub X)

> 흩어진 화물을 모아 빈 화차를 채우고, 친환경 편익을 ESG 자산으로 환전하는 AI 에이전트

철도공사의 공차율 개선과 기업의 Scope 3 ESG 공시 대응을 동시에 해결하는 B2B 통합 물류 솔루션.

- 이름의 **X** = 환경적 가치를 재무 성과로 **환전(eXchange)**, 도로 중심 물류를 철도로 **전환(eXtra Transformation)**
- 한 줄 메시지: **"철도를 채우는 순간, 물류비는 알뜰해지고 기업의 ESG 성과가 완성됩니다."**
- 핵심 차별점: 조건이 안 맞아 매칭이 깨졌을 때, **조건 조율 에이전트**(→ [3.2](#32-조건-조율-에이전트--gemini))가 화주별로 다른 설득 논리를 만들어 협상으로 되살린다

---

## 1. 문제 정의

2026년 대기업을 시작으로 ESG 공시 의무화(Scope 3 공급망 감축)가 본격화되면서 제조·유통 기업은 물류 탄소 배출량을 측정·감축해야 하는 압박을 받고 있다. 그러나 현장에는 다섯 가지 한계가 있다.

| #   | 문제                                                                                         | 결과                                            |
| --- | -------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 1   | **화물 파편화** — 중소·중견기업은 단독으로 화물열차 1편성을 채우지 못함                      | 도로 운송 고수 → 코레일 공차 발생 (수송 불균형) |
| 2   | **조건 미세 불일치** — 출발일 하루 차이, 정원까지 몇 톤 부족, 도착 시간대 차이로 합적이 깨짐 | 후보 대부분이 "매칭 실패"로 종료                |
| 3   | **환경 가치의 미측정** — 철도가 트럭 대비 탄소를 크게 적게 배출함에도 산출 수단 부재         | 담당자가 공시용 지표를 만들 수 없음             |
| 4   | **추상적 표현** — "나무 몇 그루" 수준의 마케팅 언어                                          | 지속가능경영보고서에 인용 불가                  |
| 5   | **재무 증명 부재** — 절감되는 사회적 비용이 금액으로 환산되지 않음                           | 경영진 의사결정을 이끌지 못함                   |

특히 #2가 이 서비스의 승부처다. 조건이 어긋난 사례의 상당수는 **화주가 진짜로 못 바꾸는 게 아니라, 바꿀 이유를 못 받아서 안 바꾸는 것**이다. "하루 늦추면 운임 31% 아낀다"는 걸 알면 늦출 화주가 많다.

## 2. 해결 방법

기업의 운송 주문 데이터(엑셀 / API / 자연어)를 입력받아 **① 소량 화물 AI 합적 매칭** → **② 매칭 실패 시 조건 조율(협상)** → **③ 도로 vs 철도 편익 환산**을 실행하고, 결과를 **④ K-ESG 공시 문장**으로 자동 생성한다.

```
[소량 물류 데이터 입력 (엑셀 / API / 자연어 + 제약 조건)]
                │
                ▼
[1. 화물 집적 & 공차 매칭 엔진]  ──▶ 유사 노선 그룹핑 + 코레일 빈 화차 배정
                │
         성립 ──┴── 미성립 (정원 미달 · 출발일 어긋남 · 조건 충돌)
          │              │
          │              ▼
          │   [2. 조건 조율 에이전트] ──▶ 양보 조합 탐색 + 화주별 설득 메시지 (Gemini)
          │              │
          │         수락 → 재매칭 / 거절 → 다른 조합 재탐색
          │◀─────────────┘
          ▼
[3. 사회·환경 편익 환산 모듈]   ──▶ 탄소·대기오염·사고·혼잡 비용 KRW 환산
                │
                ▼
[4. ESG 스토리텔링 에이전트]     ──▶ K-ESG 공시 리포트 초안 자동 작성 (Gemini)
                │
                ▼
[5. 대시보드 & 리포트 출력]      ──▶ 시각화 UI · 운송 예약 · PDF 인증서
```

## 3. 핵심 기능

### 3.1 AI 화물 집적(Pooling) 및 공차 최적 매칭

- 출발지·목적지·시점이 유사한 타사 소량 화물을 그룹핑
- 코레일 복귀 공차 노선과 자동 매칭하여 단가 절감·철도 수송률 극대화
- 입력 예: _"울산 공장에서 경기 물류센터까지 25톤 트럭으로 운송하던 8톤 물량의 철도 전환을 요청합니다."_

### 3.2 조건 조율 에이전트 ⭐ (Gemini)

> 매칭이 안 됐을 때 포기하지 않고, 화주들에게 조건을 조금씩 바꿔달라고 협상하는 AI.

합적은 조건이 딱 맞아떨어질 때만 성립하는데 현실에서는 거의 안 맞는다. 기존 구조라면 이런 경우가 전부 "매칭 실패"로 끝나지만, 실제로는 여기 걸리는 건이 대부분이다. 이 에이전트는 실패 직전의 조합을 **협상으로 살려낸다.**

**작동 순서**

1. **제약 조건을 자연어로 수집** — _"월말 정산 때문에 25일 전에는 도착해야 함"_, _"냉장 아니어도 되지만 비 맞으면 안 됨"_ 같은 문장을 그대로 받는다. 어떤 게 **절대 조건**이고 어떤 게 **선호**인지 AI가 구분한다.
2. **양보 가능 조건 탐색** — 누가 뭘 얼마나 양보하면 매칭이 성립하는지 조합을 찾는다.
3. **화주별로 다른 설득 논리 생성** — 여기가 핵심. 같은 편성이라도 화주마다 이익 구조가 다르므로 메시지를 다르게 쓴다.

   | 화주 | 요청하는 양보    | 그 화주에게 강조할 논리                        |
   | ---- | ---------------- | ---------------------------------------------- |
   | A사  | 없음 (기준 화주) | 즉시 전환, 운임 22% 절감                       |
   | B사  | 출발 하루 연기   | 하루 늦추는 대신 절감폭 31%로 최대             |
   | C사  | 물량 2톤 추가    | 다음 주 예정 물량 당기면 이번 편성에 무료 편승 |

4. **거절 시 재탐색** — B사가 거절하면 다른 조합으로 다시 짠다.

**왜 이 기능이 심사에서 결정적인가**

기존 구조에서 생성형 AI는 마지막에 보고서 문장을 쓰는 역할뿐이다. 매칭은 최적화 알고리즘이 한다. 심사위원이 _"그럼 생성형 AI가 없어도 되는 거 아니냐"_ 고 물으면 답이 궁색해진다.

조건 조율은 정반대다. 제약을 자연어로 해석하고, 협상 카드를 찾고, 상대별로 설득 문장을 다르게 쓰는 건 최적화 알고리즘이 못 한다. **LLM이 없으면 아예 성립하지 않는 기능**이라 생성형 AI 활용(20점) 항목을 정면으로 방어한다.

발표에서도 "매칭 성공"보다 **"실패했다가 협상으로 살려내는"** 장면이 훨씬 기억에 남는다.

**최소 구현 (거창하게 안 해도 됨)**

- 화주 3곳 더미 데이터에 제약 조건 텍스트 필드 추가 (`Shipment.constraintText`)
- **정원 미달을 일부러 만들어놓고 시작** — 시연 1분차에 "실패"가 떠야 한다
- Gemini에 화주별 제약 + 화차 정원 + 운임표를 넣고 "성립 가능한 조율안과 각 화주용 제안 메시지를 JSON으로" 요청
- 화면에 조율안 카드 3장 + 수락 버튼 하나

React라면 카드 리스트 + 수락 시 상태 변경 정도라 반나절이면 붙는다.

### 3.3 사회·환경 편익 4대 지표 정량화

1. **온실가스 감축량** — ton·km당 배출계수 적용, 배출권 시세 연동 금전 가치 산출
2. **대기오염 저감** — NOx, SOx, PM2.5 저감에 따른 사회적 피해비용 절감액
3. **교통사고 예방** — 대형 화물차 도로 점유 감소에 따른 사고비용 절감
4. **도로혼잡 완화** — 통행량 감소에 따른 혼잡비용 및 도로 유지보수비 절감

### 3.4 KRW 환산 대시보드

> "이번 분기 합적을 통한 철도 전환으로 확보한 **사회적 편익 환산 가치 총 OOO원**(운송비 절감 OOO원 포함). 대형 트럭 OO대의 도심 진입을 막은 효과."

### 3.5 K-ESG 공시 리포트 자동 생성 (Gemini)

- 산출된 정량 데이터를 근거로 K-ESG 가이드라인(E 영역: 기후변화 대응, 대기오염) 및 GRI 305 / ISSB IFRS S2 Scope 3 Cat.4 에 부합하는 본문 단락 생성
- 문구 선택 → 복사 또는 PDF 다운로드

### 3.6 규제·탄소가격 변동 대응 재계획

- 배출권 시세나 공시 기준이 바뀌면 과거 물류 데이터에 소급 적용해 환산 가치 재조정 + 추가 감축 전략 제안

## 4. 산식 정의

구현 시 계수는 **`lib/constants.ts` 한 파일에만** 두고, 계산 로직에 숫자를 직접 쓰지 않는다. (심사 중 수치 교체 요구가 들어와도 한 곳만 고치면 전체가 갱신됨)

**기준선(baseline)** = 전 구간 도로 단독 운송
**실제(actual)** = 간선 철도 + 양단 셔틀(공장↔역) 도로 운송
**편익 = baseline − actual**

```
tonKm            = 중량(ton) × 거리(km)

CO2 감축량(kg)    = (도로tonKm × 도로배출계수 − 철도tonKm × 철도배출계수
                     − 셔틀tonKm × 도로배출계수) ÷ 1000
배출권 가치(원)   = CO2감축량(t) × 배출권 시세(원/tCO2)

사회적비용 편익   = 각 항목(대기오염·사고·혼잡·도로유지)에 대해
                    도로tonKm × 도로원단위 − (철도tonKm × 철도원단위 + 셔틀tonKm × 도로원단위)

운송비 절감(원)   = 도로운임 − (철도 간선운임 × (1 − 공차할인율) + 셔틀운임)
총 가치           = 사회적편익 합계 + 운송비 절감
```

### 채워야 할 계수 (⚠️ 출처 확인 필요)

| 계수                               | 단위           | 출처                                                             |
| ---------------------------------- | -------------- | ---------------------------------------------------------------- |
| 도로/철도 CO2 배출원단위           | g-CO2 / ton·km | 국토교통부 수송수단별 온실가스 배출원단위, 국가온실가스 인벤토리 |
| 대기오염·사고·혼잡·도로유지 원단위 | 원 / ton·km    | 한국교통연구원 «교통시설 투자평가지침»                           |
| 배출권 시세 (KAU)                  | 원 / tCO2      | 한국거래소 배출권시장                                            |
| 도로/철도 운임 원단위              | 원 / ton·km    | 코레일 화물운임표, 화물자동차 운임 실태조사                      |
| 소나무 CO2 흡수량                  | kg / 그루·년   | 산림청                                                           |

## 5. 시연 시나리오

| 장면 | 내용                                                 | 확인 지표                                                                 |
| ---- | ---------------------------------------------------- | ------------------------------------------------------------------------- |
| 1    | 3개 중소기업이 소량 화물 + 제약 조건을 자연어로 등록 | "울산→수도권 3건 감지. 합계 14톤 / 정원 18톤 — **4톤 부족, 매칭 실패**"   |
| 2    | **조건 조율 에이전트 작동** (하이라이트)             | 조율안 카드 3장 + 화주별 제안 메시지 자동 생성 → C사 수락 → 편성 확정     |
| 3    | 도로 vs 철도 비교 대시보드 렌더링                    | 탄소 74% 감소 그래프, KRW 환산 카드, "소나무 4만 그루 / 트럭 45대" 시각화 |
| 4    | 'ESG 보고서 초안 생성' 클릭                          | Gemini가 K-ESG 문맥 본문 단락 작성 → 수정 → PDF                           |
| 5    | '코레일 공차 수송 확정' 클릭                         | 예약 완료 + K-ESG 성과 자산 인증서 발행                                   |

### 장면 2 대본 (발표의 핵심 60초)

> **AI:** "울산→수도권 3건 감지. 합계 14톤으로 화차 정원 18톤에 4톤 부족. 단독 배차 시 톤당 단가가 도로보다 비쌉니다."
> **AI:** "조율안을 찾았습니다. C사가 8월 22일 예정 물량 4톤을 이번 편성에 함께 실으면 3사 전원 절감. C사 단독 발송 대비 39% 절감."
> _[C사에게 보낼 제안 메시지 자동 생성]_
> **C사 응답:** 수락
> **AI:** "편성 확정. A사 22%, B사 25%, C사 39% 절감."

**시연 설계 원칙:** 1번 장면에서 반드시 "실패"가 떠야 한다. 성공부터 보여주면 조율 에이전트가 왜 필요한지 전달되지 않는다. 더미 데이터를 정원 미달로 세팅해 둘 것.

## 6. 심사 기준 대응

| 기준           | 배점 | 대응                                                                                                                                      |
| -------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 창의성         | 40   | 공급 측 과제(빈 화차)와 수요 측 니즈(ESG 성과)를 하나의 선순환 BM으로 결합. 매칭 실패를 **협상으로 되살리는** 조율 에이전트가 차별점      |
| 현업 활용성    | 30   | 화주 → 물류비 절감 + 공시 자산 / 코레일 → 공차율 감소 + B2B 영업 무기                                                                     |
| 생성형 AI 활용 | 20   | **조건 조율 에이전트(3.2)가 주력** — 자연어 제약 해석, 양보 조합 탐색, 화주별 설득 메시지 생성. 여기에 K-ESG·GRI·ISSB 규격 문장 자동 생성 |
| 구현 수준      | 10   | 공공 계수 기반 실제 계산 + 동작하는 웹 대시보드 + 문서 생성 MVP                                                                           |

> **예상 질문 방어:** _"생성형 AI가 없어도 되는 거 아니냐"_ → 조건 조율은 최적화 알고리즘으로 대체 불가능하다. 제약의 자연어 해석과 상대별 설득 문장 작성은 LLM 없이는 성립하지 않는다.

## 7. 기술 스택과 선택 근거

| 영역      | 선택                                         | 근거                                                                                                                                                                |
| --------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 프론트    | **React (Next.js 15 App Router)**            | 대시보드 UI                                                                                                                                                         |
| 백엔드    | **Next.js Route Handlers (Node/TypeScript)** | 별도 서버 없이 `FE/app/api/*`로 처리 (도메인 로직은 `BE/` 워크스페이스, 라우트는 얇게). Java Spring·FastAPI는 이번 MVP(CRUD 거의 없음, 계산+LLM 호출 위주)에서 계층 구성 비용만 큼. 서버 2개 → CORS·배포 2번 문제도 회피 |
| 타입 공유 | `BE/src/types.ts`                            | 프론트·백엔드가 동일 타입 사용. 시연 중 스펙 변경 시 수정 지점 절반                                                                                                 |
| 생성형 AI | **Google Gemini** (`@google/genai`)         | 제약 조건 해석, **조율안·화주별 설득 메시지 생성**, 리포트 문장 생성. 배선은 `BE/src/llm.ts` 한 파일에 가둬 호출부가 SDK 를 직접 쓰지 않는다 |
| 데이터    | **인메모리 시드 (`BE/src/seed.ts`)**         | 시연에 DB 불필요. 나중에 붙일 수 있게 데이터 접근부만 분리                                                                                                          |
| 스타일    | Tailwind CSS v4                              | 대시보드 속도                                                                                                                                                       |
| 배포      | Vercel                                       | `git push` 한 번                                                                                                                                                    |

> DB(PostgreSQL)·PDF 엔진은 **시간이 남으면** 붙인다. 시연 성공에 필수가 아님. PDF는 최악의 경우 브라우저 인쇄(`window.print()`)로 대체 가능.

```

    matching.ts         // 합적 + 공차 매칭 알고리즘 — 세팅 완료
    negotiate.ts        // 조건 조율 — 양보 탐색(결정론) + 설득 메시지(Gemini) — 세팅 완료
```

## 9. 구현 순서 (권장)

1. ~~`types.ts` + `constants.ts` + `seed.ts`~~ — 데이터 형태부터 확정. **시드는 정원 미달로 만들 것** (조율 시연 전제) → **완료** (14/18톤 부족 상태로 세팅됨)
2. ~~`calc.ts`~~ — 계산이 맞아야 화면이 의미 있음. 숫자 손검산 1회 필수 → **완료**, 손검산은 아직
3. ~~`matching.ts`~~ — 그리디(First-Fit Decreasing)로 충분. 최적화 알고리즘 과투자 금지. **매칭 실패 사유(부족 톤수·어긋난 날짜)를 반드시 반환**할 것 — 조율 에이전트의 입력이 된다 → **완료** (`status: "shortfall"` + `shortfallTon` + `negotiationCandidates` 반환)
4. `/api/match` + 대시보드 화면 — 성공/실패 양쪽 상태를 다 그린다 ← **여기부터 (FE 미착수)**
5. **`/api/negotiate` + 조율안 카드 화면 — 발표에서 가장 강한 장면. 4번 다음 우선순위**
6. ~~보조금 사업계획서 + K-ESG 리포트~~ → **완료** (아래 별도)
7. `/api/parse` 자연어 입력, 예약 확정 애니메이션

**조율 에이전트의 역할 분담이 핵심이다.**
"누가 뭘 양보하면 성립하는지"와 "그 양보가 그 화주에게 이득인지"는 **서버가 결정론적으로**
판정하고, LLM은 통과한 건에 대해서만 설득 문장을 쓴다. 양보 대가가 절감액보다 큰 화주는
`rejected` 로 빠지며 제안 자체가 생성되지 않는다.

발동 조건은 **마감시한**이다. `wagonPhase()` 가 `negotiate`(마감 48시간 이내 + 정원 미달)
일 때만 돌린다. 마감이 없으면 "정원 미달이면 협상"은 언제 판정할지가 없어 성립하지 않는다.

**계산과 리포트는 `report/contract.ts` 의 `ReportInput` 하나로만 연결된다.**
계산이 아직 확정되지 않아 지금은 `fixture.ts`(엔진 실제 출력을 굳힌 값)를 쓴다.
계산이 붙으면 `buildReportInput(확정편성들, applicant, period, stations)` 결과로 교체하면 되고,
리포트 코드는 손대지 않는다.

> **`result.eligible === false` 가 기본 케이스다.** 화주 실지불 운임을 baseline 으로 쓰면
> 철도 합적이 더 싸서 전환 추가비용이 발생하지 않는다. 문단·서식 모두 이 분기를 먼저 처리한다.

> AI 키가 없거나 네트워크가 끊겨도 시연이 죽지 않도록 **생성 AI 호출부에는 반드시 규칙기반 폴백**을 둔다. 해커톤 현장 와이파이는 믿을 수 없고, 무료 티어에는 요청 한도가 있다.
>
> 조율 에이전트의 폴백은 "미리 써둔 조율안 1개를 그대로 반환"이면 충분하다. 시연이 멈추는 것보다 낫다.
