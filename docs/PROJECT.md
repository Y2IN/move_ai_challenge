# 알뜰철도 X (RailHub X)

> 흩어진 화물을 모아 빈 화차를 채우고, 친환경 편익을 ESG 자산으로 환전하는 AI 에이전트

철도공사의 공차율 개선과 기업의 Scope 3 ESG 공시 대응을 동시에 해결하는 B2B 통합 물류 솔루션.

- 이름의 **X** = 환경적 가치를 재무 성과로 **환전(eXchange)**, 도로 중심 물류를 철도로 **전환(eXtra Transformation)**
- 한 줄 메시지: **"철도를 채우는 순간, 물류비는 알뜰해지고 기업의 ESG 성과가 완성됩니다."**

---

## 1. 문제 정의

2026년 대기업을 시작으로 ESG 공시 의무화(Scope 3 공급망 감축)가 본격화되면서 제조·유통 기업은 물류 탄소 배출량을 측정·감축해야 하는 압박을 받고 있다. 그러나 현장에는 네 가지 한계가 있다.

| #   | 문제                                                                                 | 결과                                            |
| --- | ------------------------------------------------------------------------------------ | ----------------------------------------------- |
| 1   | **화물 파편화** — 중소·중견기업은 단독으로 화물열차 1편성을 채우지 못함              | 도로 운송 고수 → 코레일 공차 발생 (수송 불균형) |
| 2   | **환경 가치의 미측정** — 철도가 트럭 대비 탄소를 크게 적게 배출함에도 산출 수단 부재 | 담당자가 공시용 지표를 만들 수 없음             |
| 3   | **추상적 표현** — "나무 몇 그루" 수준의 마케팅 언어                                  | 지속가능경영보고서에 인용 불가                  |
| 4   | **재무 증명 부재** — 절감되는 사회적 비용이 금액으로 환산되지 않음                   | 경영진 의사결정을 이끌지 못함                   |

## 2. 해결 방법

기업의 운송 주문 데이터(엑셀 / API / 자연어)를 입력받아 **① 소량 화물 AI 합적 매칭**과 **② 도로 vs 철도 편익 환산**을 동시에 실행하고, 결과를 **③ K-ESG 공시 문장**으로 자동 생성한다.

```
[소량 물류 데이터 입력 (엑셀 / API / 자연어)]
                │
                ▼
[1. 화물 집적 & 공차 매칭 엔진]  ──▶ 유사 노선 그룹핑 + 코레일 빈 화차 배정
                │
                ▼
[2. 사회·환경 편익 환산 모듈]   ──▶ 탄소·대기오염·사고·혼잡 비용 KRW 환산
                │
                ▼
[3. ESG 스토리텔링 에이전트]     ──▶ K-ESG 공시 리포트 초안 자동 작성 (Claude)
                │
                ▼
[4. 대시보드 & 리포트 출력]      ──▶ 시각화 UI · 운송 예약 · PDF 인증서
```

## 3. 핵심 기능

### 4.1 AI 화물 집적(Pooling) 및 공차 최적 매칭

- 출발지·목적지·시점이 유사한 타사 소량 화물을 그룹핑
- 코레일 복귀 공차 노선과 자동 매칭하여 단가 절감·철도 수송률 극대화
- 입력 예: _"울산 공장에서 경기 물류센터까지 25톤 트럭으로 운송하던 8톤 물량의 철도 전환을 요청합니다."_

### 4.2 사회·환경 편익 4대 지표 정량화

1. **온실가스 감축량** — ton·km당 배출계수 적용, 배출권 시세 연동 금전 가치 산출
2. **대기오염 저감** — NOx, SOx, PM2.5 저감에 따른 사회적 피해비용 절감액
3. **교통사고 예방** — 대형 화물차 도로 점유 감소에 따른 사고비용 절감
4. **도로혼잡 완화** — 통행량 감소에 따른 혼잡비용 및 도로 유지보수비 절감

### 4.3 KRW 환산 대시보드

> "이번 분기 합적을 통한 철도 전환으로 확보한 **사회적 편익 환산 가치 총 OOO원**(운송비 절감 OOO원 포함). 대형 트럭 OO대의 도심 진입을 막은 효과."

### 4.4 K-ESG 공시 리포트 자동 생성 (Claude)

- 산출된 정량 데이터를 근거로 K-ESG 가이드라인(E 영역: 기후변화 대응, 대기오염) 및 GRI 305 / ISSB IFRS S2 Scope 3 Cat.4 에 부합하는 본문 단락 생성
- 문구 선택 → 복사 또는 PDF 다운로드

### 4.5 규제·탄소가격 변동 대응 재계획

- 배출권 시세나 공시 기준이 바뀌면 과거 물류 데이터에 소급 적용해 환산 가치 재조정 + 추가 감축 전략 제안

## 4. 산식 정의

구현 시 계수는 **`lib/constants.ts` 한 파일에만** 두고, 계산 로직에 숫자를 직접 쓰지 않는다. (심사 중 수치 교체 요구가 들어와도 한 곳만 고치면 전체가 갱신됨)

**기준선(baseline)** = 전 구간 도로 단독 운송
**실제(actual)** = 간선 철도 + 양단 셔틀(공장↔역) 도로 운송
**편익 = baseline − actual**

```
tonKm            = 중량(ton) × 거리(km)

CO2 감축량(kg)    = (도로tonKm × 도로배출계수 − 철도tonKm × 철도배출계수
                     − 셔틀tonKm × 도로배출계수) ÷ 1000
배출권 가치(원)   = CO2감축량(t) × 배출권 시세(원/tCO2)

사회적비용 편익   = 각 항목(대기오염·사고·혼잡·도로유지)에 대해
                    도로tonKm × 도로원단위 − (철도tonKm × 철도원단위 + 셔틀tonKm × 도로원단위)

운송비 절감(원)   = 도로운임 − (철도 간선운임 × (1 − 공차할인율) + 셔틀운임)
총 가치           = 사회적편익 합계 + 운송비 절감
```

### 채워야 할 계수 (⚠️ 출처 확인 필요)

| 계수                               | 단위           | 출처                                                             |
| ---------------------------------- | -------------- | ---------------------------------------------------------------- |
| 도로/철도 CO2 배출원단위           | g-CO2 / ton·km | 국토교통부 수송수단별 온실가스 배출원단위, 국가온실가스 인벤토리 |
| 대기오염·사고·혼잡·도로유지 원단위 | 원 / ton·km    | 한국교통연구원 «교통시설 투자평가지침»                           |
| 배출권 시세 (KAU)                  | 원 / tCO2      | 한국거래소 배출권시장                                            |
| 도로/철도 운임 원단위              | 원 / ton·km    | 코레일 화물운임표, 화물자동차 운임 실태조사                      |
| 소나무 CO2 흡수량                  | kg / 그루·년   | 산림청                                                           |

> 발표 시 "실제 공공데이터 기반"이라고 말하려면 이 표의 출처 5개를 캡처해 두고 문서에 링크를 남길 것. 구현 수준 배점(10점) 방어 포인트.

## 7. 기술 스택과 선택 근거

| 영역      | 선택                                         | 근거                                                                                                                                                                |
| --------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 프론트    | **React (Next.js 15 App Router)**            | 대시보드 UI                                                                                                                                                         |
| 백엔드    | **Next.js Route Handlers (Node/TypeScript)** | 별도 서버 없이 `app/api/*`로 처리. Java Spring·FastAPI는 이번 MVP(CRUD 거의 없음, 계산+LLM 호출 위주)에서 계층 구성 비용만 큼. 서버 2개 → CORS·배포 2번 문제도 회피 |
| 타입 공유 | `lib/types.ts`                               | 프론트·백엔드가 동일 타입 사용. 시연 중 스펙 변경 시 수정 지점 절반                                                                                                 |
| 생성형 AI | **Claude API** (`@anthropic-ai/sdk`)         | 리포트 문장 생성, 자연어 파싱                                                                                                                                       |
| 데이터    | **인메모리 시드 (`lib/seed.ts`)**            | 시연에 DB 불필요. 나중에 붙일 수 있게 데이터 접근부만 분리                                                                                                          |
| 스타일    | Tailwind CSS v4                              | 대시보드 속도                                                                                                                                                       |
| 배포      | Vercel                                       | `git push` 한 번                                                                                                                                                    |

> DB(PostgreSQL)·PDF 엔진은 **시간이 남으면** 붙인다. 시연 성공에 필수가 아님. PDF는 최악의 경우 브라우저 인쇄(`window.print()`)로 대체 가능.

## 8. 폴더 구조 (예정)

```
app/
  page.tsx              // 랜딩
  api/
    parse/route.ts      // 자연어 → 구조화 화물 데이터 (Claude)
    match/route.ts      // 합적 매칭 + 편익 산출
    report/route.ts     // K-ESG 리포트 초안 생성 (Claude)
lib/
  types.ts              // 공용 도메인 타입
  constants.ts          // ⚠️ 모든 계수는 여기에만
  network.ts            // 역/노선 거리
  seed.ts               // 시연용 화물·공차 데이터
  matching.ts           // 합적 + 공차 매칭 알고리즘
  benefit.ts            // 4대 편익 계산
  claude.ts             // Claude 클라이언트 (세팅 완료)
docs/
  PROJECT.md            // 이 문서
```

## 9. 구현 순서 (권장)

1. `types.ts` + `constants.ts` + `seed.ts` — 데이터 형태부터 확정
2. `benefit.ts` — 계산이 맞아야 화면이 의미 있음. 숫자 손검산 1회 필수
3. `matching.ts` — 그리디(First-Fit Decreasing)로 충분. 최적화 알고리즘 과투자 금지
4. `/api/match` + 대시보드 화면 — **여기까지가 시연의 핵심**
5. `/api/report` + Claude 리포트 화면
6. `/api/parse` 자연어 입력, PDF 출력, 예약 확정 애니메이션

> AI 키가 없거나 네트워크가 끊겨도 시연이 죽지 않도록 **Claude 호출부에는 반드시 규칙기반 폴백**을 둔다. 해커톤 현장 와이파이는 믿을 수 없다.
